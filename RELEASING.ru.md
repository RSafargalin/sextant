# Выпуск релиза sextant

[English](RELEASING.md) | **Русский**

Релиз — это бамп версии, тег, автоматическая сборка universal-бинаря для macOS и обновление
формулы в tap'е. Большая часть автоматизирована; ручные шаги перечислены здесь, потому что
между релизами они забываются.

## Перед началом

- Версия живёт в **четырёх видах мест**. Первое проверяет релизный workflow — он откажется
  выпускать релиз при расхождении с тегом, — но остальные не проверяет никто:

  ```bash
  grep -rn "0\.[0-9]*\.[0-9]*\|0\.[0-9]*\.x" \
    Sources/SextantCore/Sextant.swift README.md README.ru.md docs/benchmarks.md docs/benchmarks.ru.md
  ```

- `main` должен быть зелёным в CI. Релизный workflow прогоняет тесты ещё раз, но обнаружить
  падение после тега — значит сжечь тег.

## 1. Подготовить версию

Выберите номер. До 1.0 изменение, ломающее флаги CLI, JSON-схемы, имена MCP-инструментов или
коды возврата, — это **минорный** бамп; всё остальное — патч. Эти четыре пункта и есть контракт
стабильности, см. [CHANGELOG.ru.md](CHANGELOG.ru.md).

1. Поднимите `Sextant.version` в `Sources/SextantCore/Sextant.swift`.
2. В обоих changelog'ах переименуйте `## [Unreleased]` в `## [X.Y.Z] — ГГГГ-ММ-ДД` и добавьте
   сверху новый пустой `## [Unreleased]`.
3. Обновите упоминания версии, которые нашёл `grep` выше: строку «версия 0.N.x» в обоих
   README, `V=…` в сниппете загрузки и строку окружения на обеих страницах замеров. Если
   замеры не переснимались, меняется только строка версии — сами числа являются записью того,
   что было измерено, и остаются как есть.
4. Прогоните полную локальную проверку:

   ```bash
   make ci
   ```

5. Закоммитьте и запушьте. **Дождитесь зелёного CI до тега.**

## 2. Поставить тег

```bash
git tag v0.7.0 && git push origin v0.7.0
```

Тег обязан совпадать с `Sextant.version` в точности, без `v`. Релизный workflow сверяет их и
падает громко при расхождении — эта проверка существует, чтобы релиз не мог врать о собственной
версии в `sextant --version` и в MCP-хендшейке.

## 3. Что делает workflow

[`.github/workflows/release.yml`](.github/workflows/release.yml) дальше без вашего участия:

- выбирает самый свежий Xcode и отказывается продолжать на тулчейне старше Swift 6.2;
- прогоняет тесты заново (тег можно поставить на коммит, который не проходил через PR);
- собирает arm64 и x86_64 раздельными проходами и склеивает `lipo`, проверяя ассертом, что в
  результате действительно обе архитектуры;
- проверяет, что бинарь сообщает ожидаемую версию и что `sextant help` отрабатывает;
- пакует архив, считает sha256 и публикует GitHub Release с архивом, файлом контрольной суммы
  и инструкцией по установке;
- печатает в тело релиза готовый блок `version` / `url` / `sha256` для формулы.

Если он упал на середине — устраните причину и перезапустите workflow на том же теге:
публикация идемпотентна, повторный прогон дозаливает артефакты, а не падает.

## 4. Обновить формулу

`Formula/sextant.rb` в этом репозитории — источник истины; в tap'е лежит копия.

1. Перенесите два значения из тела релиза в `Formula/sextant.rb`: `url` и `sha256`. Поля
   `version` там нет — Homebrew вычитывает версию из URL.
2. Закоммитьте это изменение здесь.
3. Скопируйте файл в tap-репозиторий — **[RSafargalin/homebrew-tap](https://github.com/RSafargalin/homebrew-tap)**,
   один tap на все инструменты — как `Formula/sextant.rb` и запушьте.

Имя tap-репозитория обязано сохранять префикс `homebrew-`: `brew tap RSafargalin/tap` — это
сокращение для `https://github.com/RSafargalin/homebrew-tap`, и именно эта подстановка
заставляет короткую форму работать.

## 5. Проверить опубликованное

На машине, где этой версии никогда не было:

```bash
brew update && brew trust RSafargalin/tap && brew install RSafargalin/tap/sextant
sextant --version   # должен напечатать ровно выпущенную версию
sextant help        # время сборки подтверждает, какой именно бинарь запущен
```

Обновление с предыдущей версии:

```bash
brew update && brew upgrade sextant
```

Самая сильная проверка — машина **без** Xcode-тулчейна: там обязаны работать синтаксические
команды (`map`, `api`, `search`, `lint`, `changed`), а семантические — падать с внятным
сообщением, а не выдавать неверный ответ. `sextant doctor --project <path>` должен перечислить
ровно то, чего не хватает.

## Примечания

**Бинарь не подписан и не нотаризован.** Сертификата разработчика нет. При скачивании через
браузер он получает атрибут карантина; как его снять, написано и в теле релиза, и в README. На
загрузки через Homebrew и `curl` это не распространяется.

**Пре-релизы.** Версия с дефисом (`0.8.0-rc1`) публикуется как GitHub pre-release
автоматически — workflow выводит это из тега, ничего дополнительно делать не нужно.

**После релиза** пополняйте `## [Unreleased]` в обоих changelog'ах по мере того, как изменения
попадают в main. Писать его в момент выпуска — верный способ растерять записи.
