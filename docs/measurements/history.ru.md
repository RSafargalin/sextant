# История замеров

[English](history.md) | **Русский**

[benchmarks.ru.md](../benchmarks.ru.md) показывает числа текущего релиза. Эта страница хранит
каждый замер, который та страница когда-либо публиковала, — чтобы читать динамику и оглядываться
на релиз в ретроспективе.

Правила — история стоит ровно столько, сколько её строки:

- **Только дописывать, никогда не переписывать.** Строка — запись того, что было измерено. Если
  она оказалась неверной, она остаётся и получает пометку; исправленное число — новая строка.
- **Называть бинарь.** Строка говорит, чем она снята, — выпущенным бинарём или сборкой из
  исходников на коммите, — потому что они уже расходились (см. 0.9.0 ниже). У строк, снятых до
  появления этой страницы, там, где этого никто не записал, стоит «не записано».
- **Те же входы.** Каждая строка снята на репозиториях и коммитах со страницы бенчмарков; строка
  на других входах — новая таблица, а не новая строка.
- **Релиз, который не перемеряли, строки не добавляет.** Перенести прошлые числа под новой
  версией значило бы утверждать замер, которого не было.

Количество байт не зависит от конфигурации сборки; время — зависит, и от машины тоже.

## Как добавить строку

На релизе, после бампа версии (см. [RELEASING.ru.md](../../RELEASING.ru.md)):

```bash
sextant api --project <repo> --scope <sources> | wc -c                   # сценарий A, байты
sextant api --project <repo> --scope <sources> | head -1                 # сценарий A, объявления
sextant api --project <repo> --scope <sources> --type <T> | wc -c        # сценарий B
find <repo>/<sources> -name '*.swift' -exec cat {} + | wc -c             # байты исходников
```

Для сценария C команду сценария A запускают дважды с `HOME` и `CFFIXED_USER_HOME`, указывающими на
пустой каталог: так первый прогон действительно холодный, и больше ничего на машине не задето.
В колонку «Чем снято» записывают, чем сняты числа.
