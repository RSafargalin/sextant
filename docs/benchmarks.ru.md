# Замеры — воспроизводимые, на публичных репозиториях

[English](benchmarks.md) | **Русский**

Каждое число здесь замерено на публичных open-source Swift-пакетах на закреплённой ревизии,
командами, которые вы можете выполнить сами. Ничего не зависит от приватной кодовой базы.

**Окружение:** macOS 26.5.2, x86_64, sextant 0.9.0. Сценарии A и B перезамерены для 0.9.0 на коммитах, названных ниже; сценарий C — запись замера 0.7.0, он не перезапускался.

**Репозитории** (поверхностные клоны, закреплённые ревизии):

| Репозиторий | Коммит | `.swift` файлов в исходниках |
|---|---|---|
| [Alamofire/Alamofire](https://github.com/Alamofire/Alamofire) | `0455bfb` | 43 |
| [apple/swift-argument-parser](https://github.com/apple/swift-argument-parser) | `2f77f2f` | 55 |
| [apple/swift-numerics](https://github.com/apple/swift-numerics) | `899af71` | 34 |
| [apple/swift-nio](https://github.com/apple/swift-nio) | `7297328` | 309 |
| [swiftlang/swift-syntax](https://github.com/swiftlang/swift-syntax) | `60e8eb8` | 318 |

## Что измеряется, а что нет

Единица — **байты вывода**, потому что байты воспроизводятся точно. Число токенов было бы
понятнее для бюджета LLM, но зависит от токенизатора; грубый ориентир — делить на 4. Команда
`bench` самого инструмента честна в том же: она называет свою цифру payload *относительным
прокси объёма, а не токенами*.

Сравнение верно только для задачи, заявленной в каждом сценарии. `api` отдаёт **сигнатуры и
doc-саммари, но не тела** — он отвечает на «какая у этого публичная поверхность», а не «как это
устроено внутри». Для второго читайте исходник; для этого у sextant есть команда `body`.

## Сценарий A — узнать публичную поверхность пакета

Вопрос: *«что этот пакет выставляет наружу?»* — то, что агент спрашивает, прежде чем трогать
незнакомую зависимость.

- **sextant:** `sextant api --project <repo> --scope <sources>`
- **База сравнения:** чтение всех `.swift` файлов в каталоге исходников.

| Репозиторий | Объявлений | Байт `api` | Байт исходников | Экономия |
|---|---:|---:|---:|---:|
| Alamofire | 1 226 | 170 753 | 803 997 | **78.8%** |
| swift-argument-parser | 376 | 46 724 | 461 564 | **89.9%** |
| swift-numerics | 497 | 31 911 | 181 937 | **82.5%** |
| swift-nio | 5 055 | 518 860 | 4 464 792 | **88.4%** |
| swift-syntax | 13 989 | 1 374 492 | 6 673 159 | **79.4%** |

Экономия держится в полосе **79–90%** при девятикратном разбросе размера репозитория. По краям
полосы — два вида кода, которые и так близки к чистой поверхности: swift-syntax в основном
генерируемый, с очень высоким отношением объявлений к телам, а Alamofire несёт doc-комментарии
почти на каждом объявлении, и `api` печатает их саммари — то есть большую часть своего вывода.

По сравнению с тем же замером на 0.7.0 выросла каждая поверхность: Alamofire 973 → 1 226
объявлений, swift-nio 3 672 → 5 055. В самих пакетах не изменилось ничего — коммиты те же, —
изменилась поверхность. Объявления под `#if` теперь перечисляются вместе с условием, под которым
они существуют, а внутренний `extension` с публичными членами теперь часть поверхности, которую он
несёт. Раньше и того и другого не было, то есть прежние числа мерили экономию против ответа,
который был меньше, чем должен.

## Сценарий B — узнать один тип

Вопрос: *«что такое `Session` / `ByteBuffer` / `Complex`?»* — самый частый шаг навигации на
практике.

- **sextant:** `sextant api --project <repo> --scope <sources> --type <T>`
- **База сравнения:** чтение всех файлов, где `T` объявлен **или расширен**. Чтение только
  файла с первичным объявлением не является эквивалентным ответом: в Swift публичная
  поверхность типа регулярно размазана по множеству extension-файлов, и `api --type` собирает
  их все.

| Репозиторий | Тип | Файлов с поверхностью | Байт `api` | Байт исходников | Экономия |
|---|---|---:|---:|---:|---:|
| Alamofire | `Session` | 1 | 13 110 | 85 330 | **84.6%** |
| swift-argument-parser | `ParsableCommand` | 1 | 1 720 | 10 088 | **83.0%** |
| swift-numerics | `Complex` | 11 | 6 975 | 48 287 | **85.6%** |
| swift-nio | `ByteBuffer` | 22 | 64 385 | 596 934 | **89.2%** |
| swift-syntax | `TokenSyntax` | 13 | 13 886 | 249 302 | **94.4%** |

Экономия растёт с тем, насколько широко тип расширен, — то есть ровно там, где искать
поверхность руками тяжелее всего.

> **Замечание о методике, потому что она изменила результат.** Первая версия этого сценария
> сравнивала `api --type` с единственным файлом первичного объявления. При этом `Complex` и
> `TokenSyntax` выглядели *проигрышем* (−9% и −85%): `api` возвращал поверхность из дюжины
> extension-файлов, а базой был один маленький файл. Стороны отвечали на разные вопросы. В
> таблице выше — исправленная база сравнения.

## Сценарий C — стоимость повторного запроса (кэш по content-hash)

Результаты парсинга кэшируются по хэшу содержимого, поэтому неизменное дерево не парсится
заново. Та же команда, что в сценарии A, запущенная дважды:

| Репозиторий | Холодный | Тёплый | Ускорение |
|---|---:|---:|---:|
| swift-numerics | 1.46 с | 0.18 с | 8× |
| swift-argument-parser | 3.80 с | 0.20 с | 19× |
| swift-nio | 30.45 с | 0.36 с | 84× |
| swift-syntax | 57.57 с | 0.51 с | **112×** |

Холодная цифра — честная стоимость первого контакта с большим репозиторием: полный разбор 318
файлов через SwiftSyntax занимает около минуты. Каждый следующий запрос по неизменному дереву —
меньше секунды.

Эти времена сняты на **debug**-сборке (`swift build`), то есть на том, что получается из
исходников. Парсинг SwiftSyntax без оптимизации заметно медленнее, поэтому холодная колонка
пессимистична относительно release-бинаря, который поставляется формулой Homebrew и релизом на
GitHub. На счётчики байтов в сценариях A и B конфигурация сборки не влияет.

## Как это воспроизвести

```bash
git clone --depth 1 https://github.com/apple/swift-nio.git
sextant api --project swift-nio --scope Sources | wc -c
find swift-nio/Sources -name '*.swift' -exec cat {} + | wc -c
```

Ни index store, ни сборка ни для одного замера на этой странице не нужны — `api` работает на
синтаксическом слое. Это же означает, что ничего из перечисленного не выполняет систему сборки
клонированного проекта.
