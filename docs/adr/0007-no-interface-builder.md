# ADR-0007. Interface Builder не читаем — и говорим об этом прямо

Дата: 2026-08-17
Статус: принято

## Контекст

`.storyboard` и `.xib` — это XML, в котором класс, outlet и action называются строкой. Для
инструмента, который отвечает на вопросы «кто это использует» и «что сломается», такая строка —
настоящая ссылка: класс, создаваемый только из nib, в коде не упомянут ни разу.

Замер на эталонном проекте (tea): 56 storyboard, 270 xib, **376 классов** привязано из них. И при
этом **ни одного** класса, который живёт только там: у каждого есть хотя бы одна ссылка в коде.

Значит вред от того, что nib'ы не читаются, ограничен недосчётом при оценке влияния правки. Того
случая, которого инструмент боится больше всего — уверенного «этим никто не пользуется» про
работающий класс — на этом проекте не возникает. Возникнет он только там, где nib является
единственным потребителем класса.

## Решение

Interface Builder не поддерживается и не планируется. Это записано в README (оба языка) и в
разделе роадмапа «не мы», рядом с языками вне Apple-среды.

Причина — рамка продукта, а не сложность разбора XML. В 2026 году голый Interface Builder —
редкий способ собирать приложение под Apple: интерфейс пишут в SwiftUI или в коде, а nib'ы
остаются в наследуемых частях. Чтение nib'ов означало бы второй парсер, второе понятие ссылки
(строка в XML против записи в индексе) и вторую вещь, которую надо держать честной: свежесть,
покрытие, происхождение. Инструмент строится на том, что каждый ответ знает, откуда он и чего не
видит; ещё один источник ссылок с собственными правилами удваивает эту работу ради редкой
раскладки.

## Последствия

Пользователь с nib'ами получает недосчёт в `refs`, `blast` и анализе влияния — молча, потому что
инструмент не знает, что рядом есть nib. Это принято сознательно: альтернатива — предупреждать на
каждом проекте, где найден `.xib`, то есть на большинстве наследуемых проектов, о том, что не
собираемся исправлять. Вместо предупреждения в каждом ответе — явная строка в документации и
подсказка, что делать (`grep` по nib'ам).

Если появится проект, где nib — единственный потребитель класса, решение стоит пересмотреть: тогда
речь пойдёт уже о ложном «никто не пользуется», а это другой класс ошибки, и он важнее экономии на
парсере.

## Отвергнутая альтернатива

Предупреждать в ответе, когда в проекте есть `.storyboard` или `.xib`. Отвергнуто: на tea это
предупреждение печаталось бы на каждом семантическом ответе (326 файлов), не меняя ни одного
ответа по существу, — а предупреждение, которое видно всегда, перестают читать, и вместе с ним
перестают читать те, которые важны.
